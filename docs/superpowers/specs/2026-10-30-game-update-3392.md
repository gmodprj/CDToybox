## 1. 무엇이 바뀌었나 — 한눈에

이번 갱신은 지난 넷과 **종류가 다르다.** 코드 자리만 밀린 것이 아니라

1. **메시지 ID 8개가 전부 바뀌었다**(2944 이후 두 번째 전면 재번호).
2. **AOB 10개 중 3개가 깨졌다** — 전부 `grant.cpp`(액터 조회 · 작업 디스패처 · 작업 실행 래퍼).
   레지스터 배정과 구조체 오프셋이 바뀌어 바이트열이 달라졌다.
3. **함수 안 오프셋이 바뀌었다** — 역직렬화 +0x180 → +0x188, 앞단 +0x14C → +0x158,
   검증기 +0x5E → +0x55, 휠 UI +0x486 → +0x47D. `rederive.py` 가 "옛 경로 그대로" 짚는
   전제가 처음으로 무너져 41개 중 **20개가 "못 찾음"** 으로 나왔다.
4. **함수 프롤로그가 바뀐 것이 있다** — 자격 검사 본체, skillgate 관문0.
5. **데이터 클래스 레이아웃이 통째로 재배치됐다**(§12). `ItemInfo` `_itemType` +0xA3 → +0x37,
   `_equipTypeInfo` +0x42 → +0x4A, `_maxEndurance` +0x400 → +0xE … `KnowledgeInfo`
   `_learnApplySkillInfo` +0x104 → +0x18. **bool 류가 앞으로 모이고 목록이 뒤로 갔다** —
   필드 정렬 규칙이 바뀐 것으로 보인다. 데이터 표를 오프셋으로 읽는 코드가 전부 영향을 받는다.

배포본(2976 빌드)은 **이 갱신 전에 한 번도 실행되지 않았다**(마지막 로그 09-26 12:44, 배포 13:09).

### 10.1 InfoManager 전역 은행 — 이름으로 전부 가른다

`mov rbx,[rip+G]; cmp edx,[rbx+8]` 꼴의 조회 함수(379바이트 짜리가 수십 개)가 실패 갈래에서
`lea r8,[rip+이름]` 으로 **표 이름 문자열**을 든다. 그래서 전역 → 이름이 정적으로 나온다:

```
0x71ADAD0 jobinfo        0x71ADAF8 MercenaryInfo   0x71ADB30 knowledgeInfo  0x71ADB40 iteminfo
0x71ADB50 regioninfo     0x71ADB70 skillgroupinfo  0x71ADB98 statusinfo     0x71AEC10 conditioninfo
0x71B2BF8 GamePlayVariableInfo
```

`ReserveSlotInfo` 조회(0x3DE270)는 실패 갈래에 표 이름을 안 들고 **기본 레코드** `0x7123098` 을
돌려준다 — 그 기본 레코드를 등록 함수(0x27C4350)가 `ReserveSlotInfo` 문자열 옆에서 `lea` 하므로
이름 → 기본 레코드 → 그것을 읽는 조회 함수 → `mov rbx,[rip+G]` 로 **`kSlotMgrGlobalRva = 0x71ADB60`**
을 정적으로 얻었다(2976 까지는 런타임 탐침이 필요했다). 같은 길로 지식 0x71ADB30 · GPV 0x71B2BF8 ·
조건 0x71AEC10 · 구역 0x71ADB50 이 전부 교차 확인된다.

## 12. 데이터 클래스 레이아웃 — **통째로 재배치**

`tools/rtti/fields.py` 가 3392 에서도 돈다(실패 메시지 클래스 581개). 세 가지가 한꺼번에 바뀌었다.

1. **머리가 뒤바뀌었다.** 2976 까지 `{+0 u32 키, +8 문자열 객체*}` 였던 것이 **`{+0 문자열 객체*, +8 키}`**
   다. 공통 머리 읽기 `0x15FC6F0` 이 문자열을 읽어 `0x4B89B0(레코드)` 로 `[레코드+0]` 에 꽂고, 역직렬화가
   키를 `mov [레코드+8], eax` 로 적는다(ItemInfo · KnowledgeInfo · ReserveSlotInfo · CharacterInfo · StatusInfo
   · SubLevelInfo · EquipTypeInfo · BuffInfo · PatternDescriptionInfo · SkillInfo · ConditionInfo 전부).
   **키 폭은 표마다 다르다** - CharacterInfo u32, RegionInfo·VehicleInfo u16(`_isBlocked` 가 +0xA),
   MercenaryInfo **u8**(`mov [rdi+8], al`, `_isBlocked` 가 +0x9).
2. **필드가 종류별로 재배치됐다** - bool·u8 류가 +0xC 부터 모이고, u16 참조, u32, 문자열, 목록 순.
   필드 정렬 규칙이 바뀐 것이다(컴파일러가 아니라 데이터 빌드 도구 쪽).
3. **ItemInfo 의 목록 칸이 지연 포인터가 됐다.** 2976 까지 인라인 `{ptr, u32 개수, u32 용량}`(16바이트)
   이던 목록이 ItemInfo 에서는 **그 벡터를 가리키는 8바이트 포인터**가 됐다. 읽기 함수가 플래그 1바이트를
   먼저 읽고(`r8d=1`), 0 이면 만들지 않는다(= 널 포인터 = 빈 목록). 벡터 자체의 모양은 그대로다
   (`0x17649E0`: 개수를 `[rbx+8]` 에 더하고 예약). KnowledgeInfo · ReserveSlotInfo · EquipTypeInfo ·
   SkillInfo · BuffInfo 의 목록은 **여전히 인라인**이다(읽기 함수가 u32 개수를 먼저 읽는다, `r8d=4`).
   하위 객체도 같다 - `_dropDefaultData`(0x30바이트) · `_sharpnessData`(0x48바이트)가 지연 객체다.

빈 문자열 싱글턴도 여기서 나왔다 - `0x4B89B0` 이 `[레코드+0]` 에 기본값으로 꽂는 `0x6E92D20` 이
**`kEmptyStrRva`**(2850 이후 미도출)다.
